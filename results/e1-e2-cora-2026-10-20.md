数据：cora，n = 1815（剔除 64 条无标签），118 个实体。脚本 seed 20261012，entity-disjoint 70/30 切分，超参只在 train 上调，TEST 只报一次。

## E1 collective blocking（社区级候选 vs per-record top-k）

- 调参：baseline k* = 50（train PC 网格 0.1425 / 0.248 / 0.4617）；treatment res* = 0.5（train PC 0.5898）
- TEST（train 1086 / test 729）：
  - BASELINE：pairs = 24,267，PC = 0.7050，RR = 0.9085
  - TREATMENT：pairs = 21,164，PC = 0.7298，RR = 0.9202
- **KILL LINE：dPC = +0.0248 → signal alive**
- 保留意见：
  1. 预算未对齐：treatment 比 baseline 少用 12.8% 的 pairs（脚本预注册口径 ±5%、论文版 ±2%）。少花预算还赢了，方向上是加分，但论文版必须按 ±2% 对齐重跑才算数。
  2. end-to-end 两臂指标逐项完全相同（ARI 0.0409 等 14 项全同）——全协议阶段必须核查：是 Leiden 分区对 pairs 差异不敏感，还是 e2e 评估路径有 bug。

## E2 marginal-allocation blocking（water-filling 边际分配）

- 调参：baseline k* = 50（train PC 网格 0.1679 / 0.2928 / 0.5157）；train pool pairs 242,200，阳性率 31.1%
- 校准：Platt（截距 −18.751，斜率 29.015）；混合模型 w = 0.703/0.297，mu = 0.385/0.874，sd = 0.115/0.076，分离度 0.4891
- TEST（train 1211 / test 604）：
  - BASELINE（fixed k）：pairs = 20,898，PC = 0.5865，RR = 0.8852
  - MARG-ALLOC labeled-Platt：pairs = 20,575，PC = 0.9092，RR = 0.8870
  - MARG-ALLOC unlabeled-mixture：pairs = 20,575，PC = 0.9092，RR = 0.8870（与 A 相同）
- **KILL LINE A：dPC = +0.3227 → signal alive；KILL LINE B：dPC = +0.3227 → signal alive**
- 预算差 −1.5%，已在论文版 ±2% 口径内，本结果接近 paper-grade。
- 机制证据：marg-alloc 下 56% 的记录分配到的 pairs 低于固定 k*（<k* share = 0.56，baseline 为 0）——预算从"容易的记录"流向"难的记录"，与 water-filling 的设计预期一致。

## 结论与下一步（预注册）
- 两条 kill line 均未触发，两个方向都活。E2 是量级性结果（同预算 PC +32.3 个百分点），E1 是弱阳性（+2.5 个百分点且预算未对齐）。
- Full protocol：±2% 预算对齐 + 置换检验 + 扩展数据集（D10K、MusicBrainz），E1 另需核查 e2e 两臂相同一事。
